# VeriHGN — adapted reproduction on CircuitNet-ISPD15

An academically honest, reproducible **adapted reproduction** of

> Runbang Hu, Bo Fang, Bingzhe Li, Yuede Ji. *VeriHGN: Heterogeneous Graph-Based Congestion Prediction for Chip Layout Verification.* KDD '26. [DOI 10.1145/3770855.3818099](https://doi.org/10.1145/3770855.3818099) · [official code](https://github.com/SC-Lab-Go/VeriHGN)

**How it runs.** The **unmodified official model, loss and metrics** (`third_party/VeriHGN`, commit `28a6f1e`) run on CircuitNet-ISPD15 data that this project preprocesses itself, because the authors' preprocessing is not published.

**What we do not claim.** This project does **not** claim to reproduce the numbers in the paper's Tables 2–6. Every departure from the paper or the official code is listed in [`docs/RESEARCH_TO_CODE_MAPPING.md`](docs/RESEARCH_TO_CODE_MAPPING.md), and is also written into each run's `config.yaml` under `deviations`.


**Note on `torch_scatter`.** The official model imports `torch_scatter`. If no wheel matches your torch build, a pure-PyTorch shim with identical `scatter_mean` / `scatter_add` semantics is installed automatically (`tests/test_compat_and_io.py` checks it). The implementation in use is written to every run's `env.json`.

## Colab (A100) workflow

1. On the laptop, run `.venv\Scripts\python tools\make_colab_bundle.py`. This writes `dist\verihgn_code.zip` (~0.1 MB; code only, no data).
2. Upload it to Google Drive as `MyDrive/VeriHGN/code/verihgn_code.zip`.
3. Add a Drive shortcut to the [CircuitNet folder](https://drive.google.com/drive/folders/1GjW-1LBx1563bg3pHQGvhcEyK2A9sYUB): *Organize → Add shortcut → My Drive*.
4. In Colab, choose *Runtime → A100 GPU*. Open the notebooks from `notebooks/` in order:

| Notebook | Does | Typical time (estimate) |
|---|---|---|
| `01_environment_setup` | GPU/CUDA/RAM/library report, Drive access test (I-1), storage check (I-2) | 2–3 min |
| `02_dataset_fetch_and_audit` | Extracts the 9 official-scope designs + 6 routability maps to local disk; integrity, discovery and shape audit | 15–30 min per session |
| `03_preprocessing` | `processed/ispd15/<prep_hash>/…` on Drive (written / skipped / failed counted); full processed-data audit; both splits | 10–20 min, once |
| `04_graph_construction_validation` | Every sample × 6 variants through every validation gate; official model forward/backward per design on the GPU | 15–40 min, once |
| `05_gpu_profiling_and_precision_benchmark` | Gate → data-loading/graph-memory profile → per-design peak VRAM → run-dir inspection + checkpoint tests → smoke test with resume → FP32/FP16/BF16 benchmark (off by default) → persistence check → `STAGE_REPORT.md` | ~20–40 min without the benchmark; benchmark ~2–4 h (resumable) |
| `06_training_diagnosis` | Part A: read-only collapse inspection of the smoke checkpoint · Part B (off by default): 60-step instrumented FP32 vs FP16 diagnostic. See [`docs/SMOKE_TRAINING_DIAGNOSIS.md`](docs/SMOKE_TRAINING_DIAGNOSIS.md) | A: 5–10 min · B: 5–15 min |
| `07_collapse_experiment` | Controlled collapse experiment (smoke replicas FP16/FP32 + training-set size/diversity arms, normal engine). Cell 1 plans only; the run is **off until approved**. See [`docs/COLLAPSE_EXPERIMENT_PLAN.md`](docs/COLLAPSE_EXPERIMENT_PLAN.md) | plan < 1 min · run ≈ 35–65 min (estimate) |
| `08_headpath_experiment` | **Diagnostic deviation, not a reproduction.** Two arms (official vs. cell-head clamp omitted in training only) × 6 paired seeds + test–retest, official evaluation for both. Run **off until approved** and blocked while research decisions are pending. See [`docs/HEADPATH_PLAN.md`](docs/HEADPATH_PLAN.md) | plan < 1 min · run ≈ 55–110 min (estimate) |
| `09_results_export` | **Read-only, CPU only.** Exports HEADPATH (and the notebook-07 context) into a validated, lossless offline-dashboard bundle (`MyDrive/VeriHGN/export/`) with an integrity report; sources hashed before/after. See [`docs/DASHBOARD_EXPORT.md`](docs/DASHBOARD_EXPORT.md) | ≈ 10–25 min (estimate) |

Times are estimates, not measurements, until the notebooks have run on your A100. There is no full-training notebook in this stage (approval required). Step-by-step instructions: [`docs/STAGE2_RUNBOOK.md`](docs/STAGE2_RUNBOOK.md).

After a Colab disconnect:

1. Re-run the bootstrap cell, plus notebook 02 if raw data is needed (it lives on `/content`).
2. Re-run the training cell.
3. Training resumes from `MyDrive/VeriHGN/runs/<run_id>/checkpoints/last.pt`.
