# HEADPATH: train-time cell-head clamp experiment (pre-registered diagnostic)

**Status (2026-10-20):** implemented, validated on synthetic CPU data, all research decisions final (§9).
- **Not run.** Nothing has been trained on the GPU.
- **Gated.** `RUN_HEADPATH = False` in notebook 08; running it needs your explicit approval.

> **This is not a reproduction of VeriHGN.** Arm **U** deviates from the official model (§2). Its results may never be reported as reproduction results or mixed with them. Arm **O** is the unmodified official model.

**Sources:**
- Rationale: `docs/POST_COLLAPSE_FORENSIC_REPORT.md` §§1–11.
- Pre-registration: `configs/headpath_manifest.json`, generated by `tools/make_headpath_manifest.py` from sample names and the constants in `src/verihgn_repro/diagnostics/headpath.py`.

## 1. Question and hypotheses

In 17 of the 18 notebook-07 runs, the cell head's validation predictions are exactly 0 at the end. With the official `clamp(min=0)`, a dead head receives exactly zero gradient, so no official run can show whether the head *could* have learned.

| | Hypothesis | Pre-registered evidence |
|---|---|---|
| **H-dyn** | The train-time clamp kills an otherwise learnable cell head | arm U `LEARNS_AND_GENERALIZES` where arm O does not (primary test, §5) |
| **H-sig** | The cell branch lacks learnable signal | arm U `ACTIVE_WITHOUT_USEFUL_SIGNAL`: active head, clamped WMSE within ±3 % of the zero predictor, pooled cell Spearman ≤ 0.05. Reported as seed counts, separately from the primary test |

**What this experiment does not isolate (R8).** It cannot separate "the clamp removes the gradient" from "the clamp changes the loss surface". Removing the clamp in training does both:
- the weighted MSE now also penalizes negative outputs;
- the variance regularizer sees raw spread.

A straight-through arm would isolate the gradient pathway. By decision R8 it is not included.

## 2. Arms and the deviation

| | Arm O (official) | Arm U (diagnostic deviation) |
|---|---|---|
| Model | `third_party/VeriHGN` `VeriHGN`, unchanged | Same object; only `cell_head` is re-classed (`model_deviations.apply_cell_head_train_unclamped`) |
| Cell head, training forward | `mlp(h).squeeze(-1).clamp(min=0)` | `mlp(h).squeeze(-1)` (raw, can be negative) |
| Cell head, eval forward | official `PredictionHead.forward` | **official `PredictionHead.forward`** (`super().forward`) |
| Grid head | official | official |
| Training loss | official `verihgn_loss` on the clamped outputs | official `verihgn_loss`, with **raw** cell outputs in both the weighted MSE and the variance regularizer (R9; part of the deviation) |
| Config flag / run id | `model.cell_head_train_clamp: true` / unchanged | `false` / suffix `__DEV-cellhead-train-unclamped` |

**What the re-classing preserves.** It creates no module, adds no parameter and consumes no RNG. Parameter names, order and `state_dict` keys are unchanged (T2, T3).

**The grid head is not a clean within-run control.** Its code is official, but 67 % of the parameters are shared. In arm O a dead cell head leaves the trunk effectively grid-trained; in arm U both heads train it. Grid differences between arms are therefore expected.

**Unchanged by design and verified by tests:**
- `third_party/` (T1);
- labels, features, graphs and splits (the selection is the notebook-07 FULL arm, T16);
- AdamW, clipping, schedule (T17);
- the official evaluation functions (`evaluation/evaluate.py` and `utils/evaluation.py` are untouched).

## 4. What is logged: three cell-prediction streams, kept apart

**Per step** (`steps.csv`, `training.step_log_heads`):
- **Raw** stream: the pre-clamp head output, read by a hook. Logged as `cell_raw_*` and `cell_wmse_raw`.
- **Clamped-training** stream: `clamp(cell_pred, min=0)`, the official prediction. Logged as `cell_clamped_*` and `cell_wmse_clamped`.
- **As entered the loss** (arm O: clamped; arm U: raw): `cell_wmse_loss`, `var_cell_loss`.
- **Grid:** `grid_wmse_loss`, `var_grid_loss`, `grid_pred_*`.
- **Zero predictor:** `cell_wmse_zero`, `grid_wmse_zero`, `var_*_zero`.
- **Gradients:** the pre-clip gradient norm of the cell-only / grid-only / shared parameters (`grad_norm_*`), plus all existing columns.

**Per evaluation** (`evals.csv`):
- **Official-evaluation stream** (`val_*`), per head:
  - official metrics (pooled);
  - independent Pearson and Spearman (NaN when undefined);
  - prediction std, zero fraction, mean and max;
  - **activity class**;
  - eval-mode raw statistics (`val_*_evalraw_*`).
- Per design (`design_<d>_*`, including matrix_mult_a).
- The tile-projection reference (`tileproj_*`).

**Per epoch** (`history.csv`):
- Training metrics on **clamped** predictions; arm U additionally has `train_cell_raw_*` (R6).

**At the end:**
- official-evaluation validation predictions in `predictions_val_official/`;
- the fresh-official-model check (§6).

> Never compare arm U's raw training loss with arm O's training loss (R6). Only clamped quantities are comparable.

## 5. Outcomes (pre-registered, final)

**Activity, kept separate from generalization (R2).** This applies to each head, at each evaluation:
- `DEAD`: zero fraction = 1.
- `DEGENERATE`: not dead, but validation std < 1e-4 or zero fraction ≥ 0.999.
- `HEALTHY`: otherwise.

The activity class says nothing about correlation. This replaces forensic report §3.3, which also counted ρ ≤ 0 as degenerate.

**Criteria (per run, cell head):**

| | Definition |
|---|---|
| **P1 (active)** | Final (step-490) cell activity = `HEALTHY` **and** cell predictions all 0 on ≤ 10 % of the last 50 training steps |
| **P2 (learns)** | improvement = 1 − Σ `cell_wmse_clamped` / Σ `cell_wmse_zero` over the last 98 steps. **Clamped in both arms (R1), and the same zero-predictor reference in both arms of a pair (decision 1; enforced).** PASS if ≥ 0.12; FAIL if ≤ 0.08; BORDERLINE if strictly between |
| **P3 (generalizes)** | pooled independent validation cell Spearman at step 490 ≥ 0.10 (NaN = fail) (R5: primary is pooled) |
| **H-sig** | P1, and \|improvement\| ≤ 0.03, and pooled independent cell Spearman ≤ 0.05 (NaN never satisfies it) |

**Run categories (R3 + decision 2; mutually exclusive, checked in this order):**

| Category | Rule |
|---|---|
| `INVALID` | any validity check fails (§6); reported, never dropped |
| `CELL_HEAD_FAILURE_PERSISTS` | not P1 |
| `LEARNS_AND_GENERALIZES` | P1, P2 = PASS, P3 |
| `LEARNS_WITHOUT_DEMONSTRATED_GENERALIZATION` | P1, P2 = PASS, not P3 |
| `ACTIVE_WITHOUT_USEFUL_SIGNAL` (H-sig) | H-sig criteria met (this implies P2 = FAIL) |
| `INCONCLUSIVE` | everything else, including P2 BORDERLINE, and active heads with 3–8 % improvement |

**Primary statistical test (R4, decisions 3–4).**
- **Test:** the exact McNemar test for paired binary outcomes, which equals a two-sided exact binomial sign test on the discordant pairs.
- **Data:** the six independent paired seeds 42–47 on the endpoint `category == LEARNS_AND_GENERALIZES`. Retest runs never enter it.
- **Reported:** valid pairs, discordant pairs, U-only and O-only counts, effect direction, exact p.
- **Excluded pairs:** pairs with an invalid run, or with differing zero-predictor references, are excluded and listed.
- **Significance:** only p ≤ 0.05 counts. With 6 pairs that requires all 6 pairs discordant in one direction (p = 0.03125); 5/5 gives p = 0.0625. Otherwise the result is "not statistically conclusive", and no significance is claimed.
- **H-sig is not folded into this test.** It is reported as the number of seeds meeting the H-sig criteria per arm, with the seed list; no test is applied.

**Secondary and descriptive outcomes (never decide the conclusion):**
- **Grid head per arm:** activity, clamped WMSE against the zero predictor, pooled ρ.
- **Per-design and matrix_mult_a-only metrics** (R5).
- **Both-head collapse** by the notebook-07 rule.
- **Tile-projection reference:** the cell Spearman of `grid_pred[tile(cell)]`.
- **Non-learned baseline** (decision 6, §5a).
- **Test–retest |Δ|:** of P2, the final cell ρ and the final grid ρ, plus whether the category repeats.

**Historical replication (R7, decision 5).**
- **Check:** the arm-O end state at global step 245 should match notebook-07 FULL for seeds 42–44: cell DEAD / grid DEAD, DEAD / DEAD, and DEAD / not-DEAD. The 07 data support DEAD vs not-DEAD only; collapse steps are not required to match.
- **If it fails:** it is flagged prominently (`historical_replication: FAILED`, a WARNING at the start of the conclusion) and must be investigated.
- **It does not invalidate the experiment.** The report keeps two separate verdicts:

| `experiment_status` | Meaning |
|---|---|
| `VALID` | all 12 primary runs present and valid, and every pair has the same zero-predictor reference |
| `INVALID` | at least one primary run invalid, or a pair check failed |
| `INCOMPLETE` | primary runs missing |

`verdict` combines the two verdicts, for example "VALID - HISTORICAL REPLICATION FAILED (investigate)".

## 5a. Non-learned cell baseline and per-graph standardization (decision 6)

**Definition.** For each of the 5 paper_eq3 grid input features (cell density, pin density, net density, mean cell area, mean net HPWL), the Spearman between the feature value of the cell's tile, as given to the model, and the cell label. It is reported:
- pooled over the 12 validation graphs;
- per design;
- per graph (`sample_*`);
- as the per-design mean of the per-graph values (`design_*_mean_of_samples`).

It is descriptive only.

**How per-graph standardization affects the numbers.** The official builder standardizes every feature per graph: `(x − mean) / max(std, 1e-6)`.
- **Per graph:** that map is strictly increasing within a graph, so every per-graph Spearman is identical to the raw-feature one. T14b checks this with an arbitrary positive affine map per graph.
- **Pooled:** pooling several graphs ranks values from different graphs on a common scale they do not share, which can move the pooled value either way. This affects the pooled baseline, and `design_mgc_matrix_mult_a_*`, which pools 6 graphs. The single-graph designs are unaffected.
- **Comparability with the model:** the model sees the same standardized inputs. Pooled baselines are therefore the right "what do the inputs alone rank" reference for the pooled cell-head Spearman, but they are not raw-feature results.
- **Robust summary:** use the per-graph values and their per-design means, which are standardization-invariant.

## 6. Validity (per run; a run that fails is INVALID, still reported)

A run is valid only if all of these hold:
- 490 logged steps, with all losses and gradient norms finite;
- evaluations at exactly the 11 pre-registered steps;
- `last.pt` at epoch 2;
- AdamW `step` = the number of `optimizer.step()` calls in the log;
- all parameters and Adam moments finite;
- **the fresh-official-model check passes** (decision 7). The final weights are loaded into a freshly built official model, and every validation prediction must satisfy `|a − b| ≤ atol + rtol·|b|` with **atol = 1e-6 and rtol = 1e-6**. Recorded alongside: max |Δ|, max relative Δ, the worst tolerance ratio, and the self-repeat difference of the run's own model (GPU scatter non-determinism). On the CPU this is exactly 0 (T4, T19).

The pair check (`experiment_status`) also requires both arms of each seed to have the same zero-predictor reference: the same sample sequence and Σ zero-predictor WMSE over the P2 window.

## 11. Outputs, failure handling and preservation (execution-path hardening, 2026-10-21)

**Run folders.** `runs/headpath/<run>/`, one per arm, seed and retest, each with its own run id and checkpoints.

**Failure isolation and complete reporting** (`headpath.run_plan`, `headpath.execute`):
- **Every run is isolated.** An exception in a run is caught and recorded as `run_status: FAILED`, with exception type, message, full traceback, whether it was runtime-fatal, and the trainer's `status.json`. The next run then starts.
- **When the remaining runs are not started.** After a *runtime-fatal* error, or an interrupt, the remaining runs are recorded as `NOT_STARTED`, with the reason.
  - Runtime-fatal errors: CUDA or accelerator errors such as an illegal memory access or a device-side assert, host `MemoryError`, or a failed CUDA probe after the error.
  - Interrupts (`KeyboardInterrupt`, `SystemExit`) are recorded, then re-raised.
  - A CUDA out-of-memory error alone is not fatal: memory is released and the CUDA probe decides.
- **Run statuses.** `COMPLETED` means the trainer finished and the run was summarized. `INCOMPLETE` means the trainer returned without finishing. Only COMPLETED runs carry results; a failure is never turned into a result.
- **The report always lists all 14 planned runs, in plan order.** It is written atomically (temporary file, fsync, rename) before the first run and again after every run, failed runs included. If graph building fails, it lists all 14 as `NOT_STARTED` with the error.
- **Experiment status.** It is `VALID` only if all 14 runs are COMPLETED and valid and every pair check passes. Otherwise it is `FAILED` (any failed run), `INVALID` (any invalid run or pair check) or `INCOMPLETE` (any run not started, incomplete or missing), and `status_reasons` lists all of them. The notebook prints a banner whenever the status is not VALID.

**Protected artifacts.** These are never written, and are verified by content:
- **What is fingerprinted:** every file under `runs/verihgn_ispd15_smoke__*`, `runs/precision_benchmark` and `runs/collapse_diag`, plus `reports/05_*`, `06_*`, `07_*` and `STAGE_REPORT.md`.
- **How:** the SHA-256 of the full content of every file, checkpoints included, taken before the run and, in a `finally` block, after it, even when a run fails.
- **What counts as a change:** an added, removed or content-changed file. An mtime-only change is reported but is not a modification.
- **Where it is recorded:** the comparison goes into the report (`protected_artifacts`). Any change raises `ProtectedArtifactError` at the end.
- **The runner refuses** any output path under `runs/collapse_diag`.

**Drive durability.** The last step of the run cell, always, after every report write, is `colab.flush_drive`:
1. it records the SHA-256 of the report and the plan;
2. it calls `drive.flush_and_unmount()`, which blocks until everything written in the session has been uploaded;
3. with `VERIFY_AFTER_REMOUNT = True`, the default, it remounts Drive (this may show the authorization popup) and re-hashes both files.

Any failure raises `DrivePersistenceError`. Nothing is written to `/content/drive` after the flush: a write there would land on the VM disk, not on Drive. If the runs failed too, the run error is raised first and the flush error is attached to it.

**Resume safety** (`training/trainer.py`, which applies to every notebook):
- **Config check:** a checkpoint is resumed only if the complete stored configuration equals the current one. The only keys allowed to differ are `training.max_epochs_this_session` and `paths.*`. A mismatch raises `CheckpointError` naming the keys, and nothing is written.
- **Environment record:** `env.json` records the *first* session and is never overwritten; every session also writes `env_session_NNN.json`. On resume, `config.yaml` is not rewritten (it was just verified equal).
- **Interrupted first attempt:** an attempt that wrote no checkpoint is moved, never deleted, into `aborted_attempt_<ts>/`, and the run restarts. This includes a crash between epoch 1's history write and its checkpoint. On the CPU the restart reproduces an uninterrupted run exactly.
- **Lost checkpoints are still refused:** more logged epochs, or a `completed` status, without a checkpoint mean lost checkpoints, and restarting from scratch is refused, as before.

**Atomic prediction export** (`headpath.export_predictions_atomic`):
- The validation predictions are written to `predictions_val_official.tmp_<pid>/`, a `_COMPLETE.json` marker (the SHA-256 of every file) is added, and the directory is renamed to `predictions_val_official/`.
- **Only a directory whose marker matches every file counts as complete.** A partial or tampered final directory, or a leftover temporary one, is moved aside to `predictions_val_official.partial_<ts>[_k]` (never deleted, never used) and the export is redone.

**Reports and names.** `reports/08_headpath_plan*.json` and `reports/08_headpath_experiment*.json` never overwrite an existing file. If the name is taken, they get a timestamp and then a counter (`headpath.new_report_path`).

**Re-running the run cell.** Completed runs are only re-loaded, never re-trained or re-saved. An interrupted run resumes from its last epoch checkpoint (after the config check). Failed runs are retried.
